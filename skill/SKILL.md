# e-larping reverse engineering — skill

Método para conocer una empresa de e-commerce en su totalidad por reverse engineering y convertirlo en una empresa nueva (dropshipping con IA + UGC) y en un pipeline reutilizable para generar tiendas. Derivado del sprint MD Dental (WO-MD-2026-11-11) y del método de reverse engineering de contenido (Cambridge / reels).

## Cuándo usarla
- Investigar un e-commerce (o varios) a fondo: web, stack, SEO/GEO, redes, embudo, precios, logística.
- Generar una tienda desde cero lista para despliegue (Cloudflare + DB + webhooks + flujos).
- Proponer una empresa dropshipping con contenido UGC orgánico, sin inventario ni ads pagados.

## Método (fases encadenadas, paralelismo interno)
1. **Fase 0 — Fundación.** Repo + espacio de estado + esta skill. Referencia de identidad: reverse engineering básico de una página premiada (Awwwards) con la identidad objetivo (p. ej. "oscura" y "elegante"): paleta, tipografía, composición.
2. **Fase 1 — Sitio ancla.** Un frente por dimensión, en paralelo, archivos exclusivos por frente:
   - Front end (estructura, UX, checkout).
   - Back end + stack (observado vs inferido, con evidencia y confianza).
   - SEO/GEO y presencia digital.
   - Redes sociales + embudo (ritmos, screens, captions, como el método Cambridge).
   - Precios (promos, volumen, bundles/Mystery Box, efecto espera).
   - Logística como hipótesis derivada (inventarios, mensajería, costos de empresa similar).
   - Pain points de clientes (reseñas y quejas públicas).
3. **Fase 2 — N sitios más.** Mismo informe por sitio; la lista se aprueba antes de investigar.
4. **Fase 3 — Síntesis + pipeline.** Comparativa de patrones y pipeline de generación desde cero: Cloudflare, base de datos, webhooks, flujos (auto-respuesta de correos, control de inventarios). Docs + plantillas + scripts.
5. **Fase 4 — Propuesta de empresa.** Producto sin inversión (proveedores directos), marketing orgánico/viral con UGC, pain points resueltos.

## Contratos
- Cada fase: alcance, fuentes, restricciones, entregables, criterios de aceptación.
- Verificación global al cierre de cada fase antes de darla por hecha.
- Estado vivo en el espacio; lo duradero en el repo.

## Reglas duras
- Distinguir observado / inferido / no verificado. Lo inferido es hipótesis con evidencia, nunca hecho.
- No inventar métricas, precios ni anuncios. No extraer datos personales en masa.
- Nada se publica, se contacta ni se gasta sin aprobación con texto exacto.
- El conector de GitHub NO crea repos: crear el repo vía navegador.
- Actualizar esta skill cuando el método mejore con evidencia real.
